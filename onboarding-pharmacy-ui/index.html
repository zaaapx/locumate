For developers: buttons above the keyboard

While the keyboard is open, the screen's primary button sits right above it; secondary actions hide until the keyboard closes. The focused field and its suggestion stay visible above the button. On a real phone this prototype does the same with the system keyboard.

No Element Plus 1.0.2 component does this: it's a custom wrapper around the bottom bar. Android usually resizes the webview, so a bottom-fixed bar already lands above the keyboard (check the app's setting on a device). iOS doesn't resize: read the keyboard height from WebToNative WTN.on("keyboard") (Android height ÷ devicePixelRatio) or from window.visualViewport, store it in a CSS variable and lift the bar by it, keeping the safe area. The iOS bar with ‹ › Done and the "From Messages" / "From My Card" suggestions is drawn by the system; the button goes above it. For the SMS code, autocomplete="one-time-code" makes iOS offer it.

Untested sketch for the developers, not run in the app.

// useKeyboardInset.js — Vue 3
import { onMounted, onBeforeUnmount } from 'vue'
export function useKeyboardInset() {
  const set = h => document.documentElement.style.setProperty('--kb', `${Math.max(0, h)}px`)
  const onVV = () => set(window.innerHeight - window.visualViewport.height)
  onMounted(() => {
    window.visualViewport?.addEventListener('resize', onVV)
    window.WTN?.on?.('keyboard', e => set(e.data.visible ? e.data.height / (/Android/.test(navigator.userAgent) ? devicePixelRatio : 1) : 0))
  })
  onBeforeUnmount(() => window.visualViewport?.removeEventListener('resize', onVV))
}

/* bottom bar */
.sticky-cta {
  position: fixed; left: 0; right: 0;
  bottom: var(--kb, 0px);
  padding: 12px 24px calc(12px + env(safe-area-inset-bottom));
  transition: bottom .2s;
}
